# 우마노트

우마무스메 한국서버 플레이어를 위한 웹 서비스입니다. 일본서버가 한국서버보다 476일 앞서 있다는 점을 이용해, 일본서버 일정을 한국서버 예상일로 바꿔 보여주고 목표 픽업까지 모일 쥬얼(사료)을 계산합니다.

로그인 없이 누구나 모든 기능을 쓸 수 있습니다.

## 기능

| 화면 | 경로 | 내용 |
| --- | --- | --- |
| 홈 | `/` | 오늘 날짜, 진행 중·다음 픽업, 오늘 앞뒤 기간의 픽업 노선도, 사료계산기에 입력한 보유 쥬얼 요약 |
| 가챠 일정 | `/gacha` | 한 달 단위 픽업 일정. 육성 우마무스메 / 서포트 카드 필터, 달 이동, 유료 쥬얼 전용·특별 가챠 표시 |
| 뽑기 시뮬레이터 | `/simulator` | 실제 배너와 제공 비율로 단차 / 10연차, 천장 포인트(200) 교환, 배너별 뽑기 기록과 통계 |
| 사료계산기 | `/calculator` | 지금 가진 쥬얼·티켓과 받을 보상을 넣고 목표 픽업을 고르면, 그날까지 모이는 쥬얼과 뽑기 횟수를 계산 |
| 생일달력 | `/birthdays` | 1월~6월 캐릭터 생일을 달별 달력으로, 다음 생일과 D-day |
| 이벤트 일정 | `/events` | 게임 이벤트를 한 달 달력에 기간 막대로 표시하고 아래에 목록으로. 경기 / 스토리 / 육성 / 기념 미션 필터 |

### 사료계산기 상세

- 입력: 무료·유료 쥬얼, 육성·서포트 티켓, 월정액, 시즌 패스(무료 / 프리미엄), 팀 경기장 클래스, 챔피언스 미팅 리그와 결승 결과, 리그 오브 히어로즈 최종 랭크, 레전드 레이스 1착 여부, 목표 픽업
- 목표로 고를 수 있는 픽업: 지금 일본서버에서 진행 중인 픽업까지(한국 예상일 기준 오늘부터 476일 안에 시작하는 픽업). 한국서버 미래 일정에 아직 없는 일본서버 배너는 일본 날짜 + 476일로 옮겨 넣고 "날짜 예상"으로 표시합니다.
- 기존 일일 미션·로그인 보너스·월정액·패스·팀 경기장 클래스 수입을 유지하며, 게임 내 이벤트(챔피언스 미팅, 리그 오브 히어로즈, 레전드 레이스, 스토리·주년·G1 기념 미션, 인자연구, 레이싱 카니발, 기능시험 등)와 운영팀 별도 지급(점검·오류 보상, 파카라이브, 기념 선물)의 누락분을 추가합니다. 상시 교환소·일반 성장 보상은 추가 수집 대상이 아닙니다. 기존 UI와 입력 필드는 유지합니다.
- 유료 쥬얼 전용 가챠는 유료 쥬얼로만 계산
- 자동 수집에서는 신데렐라 그레이 방영 기념 쥬얼 캠페인을 제외하며, 사용자가 직접 지정한 시트의 과거 지급 행은 해당 한국 날짜 그대로 포함합니다.

보상 데이터는 2026-11-23에 GameTora와 [uma.guide Pull Planner](https://uma.guide/pull-planner/)를 대조했습니다. 사용자가 지정한 [보상 시트](https://docs.google.com/spreadsheets/d/19NUeKGgrOprVmuYos0m6I6Bx0Q_JqtHi6aLGqnlLnvA/edit)의 해당 행이 있으면 시트의 수량과 한국 날짜를 우선합니다. 그 밖에는 일본 날짜를 변환하고, 한국 일정이 확인된 스토리 이벤트는 실제 한국 일정을 사용합니다. UI 파일과 입력 화면은 변경하지 않았습니다.

상점 월간 교환의 티켓 교환 횟수는 [VIPでウマ娘 Wiki ショップ](https://wikiwiki.jp/vip_umamusu/%E3%82%B7%E3%83%A7%E3%83%83%E3%83%97) (일본서버, 2026-11-22 갱신)을 따릅니다.

- 사용자 시트: `lib/data/sheetRewards.json`에 챔미 20회, 말오스 11회, 스토리 23회, 레전드 26회, 인자연구 20회, 기능시험 8회, 마스터즈 9회, G1 미션 64건, 신캐 스토리 25건의 총 206개 행과 일반·프리미엄 트레이닝 패스 보상표를 보존합니다. 챔미·말오스의 현재 선택 결과를 고정하지 않고 원본 `PVP 보상`의 순위별 표를 기존 선택 항목에 연결합니다.
- 추가 탭: `additionalRows`에 ‘기타 잡 사료’ 40건과 ‘시나리오, 로그인 사료’ 198건을 저장합니다. 주년 카운트다운·특별 로그인·미션·기념 상점, 시나리오 공개·평가점, 점검·콜라보·협동 이벤트·별도 지급과 시트에 명시된 메인 스토리 두 묶음을 포함합니다. 원본 Number 콜라보의 4행/62행 중복은 한 번만 계산하고 중복 행 번호를 기록합니다. 셀에 적힌 SSR 확정권은 전용 티켓 1장으로 보존하며 일반 서포트 티켓으로 환산하지 않습니다.
- 추가 탭은 캠페인·보상 종류·원본 일본 날짜를 대조해 기존 데이터와 수동 운영 선물을 교체합니다. 주년 로그인은 원본 수집 자료의 시작일이 밀려 있어도 동일 캠페인을 찾아 시트의 일차별 지급일을 사용합니다. 시트의 기념 상점에 포함되지 않은 별도 전용 티켓은 유지합니다. UMA Summer의 360주얼·SSR 확정권·조각은 기존 개인 보상·스토리·전체 보상에 다시 더하지 않습니다. 다른 캠페인이나 같은 날의 파카라이브 선물은 별개로 유지합니다.
- 시트의 이벤트 합계는 기존 개최 보상 및 그 합계에 포함된 별도 미션을 교체합니다. 실시간 갱신과 수집 스크립트가 시트 값을 덮어쓰지 않습니다. 시트의 마지막 개최 이후에도 같은 종류의 일정이 수집되면 해당 종류의 최신 시트 보상(스토리 2,910, 인자연구 1,200, 기능시험 2,000, 마스터즈 4,500, G1 미션 150, 신캐 스토리 80주얼과 각 행의 티켓·무지개 조각)을 자동 적용합니다. 개최별 합계·교환소·첫 클리어·미션을 합계 하나로 교체하며 같은 이벤트에 추가로 더하지 않습니다. 같은 날 출시된 서로 다른 신캐는 각각 계산하고 의상·복각은 재합산하지 않습니다.
- 일본 개최 일정은 GameTora의 스토리·대회·미션·캐릭터 최초 출시 자료와 uma.guide의 인자연구·기능시험·마스터즈 개최 자료를 1시간 캐시로 조회합니다. 같은 주기로 일본의 신규 특별 로그인·한정 미션·주년 선물도 실제 데이터에서 읽습니다. 로그인은 일차별로 분리하고 같은 일차의 여러 보상 슬롯·행을 모두 합칩니다. 원본의 일반 로그인·컴백·상시 미션은 추가하지 않습니다. 외부 모듈은 데이터 리터럴만 읽고 코드를 실행하지 않습니다. 미발표 날짜는 생성하지 않으며 조회 실패 시 기존 일정과 스냅샷을 사용합니다.
- 신규 시나리오의 일본 공개가 로그인·미션 자료에서 확인되면 시트의 최신 기념 미션(500주얼·티켓 각 1장·무지개 조각 1개)과 평가점(300주얼·티켓 각 1장·무지개 조각 2개)을 해당 날짜에 자동 적용합니다. 한정 미션 그룹과 시나리오 이름을 대조해 기존 세부 보상을 교체하며 같은 날의 G1 등 다른 이벤트는 유지합니다. 여러 날 로그인하더라도 시나리오 보상을 반복 생성하지 않습니다. 이벤트 총량은 시트의 종류별 예상량을 유지하고 새 로그인·운영 선물은 원본에 명시된 지급량을 사용합니다.
- 운영팀 선물, 일일 미션·로그인·월정액·팀 경기장과 시트에 보상표가 없는 이벤트 종류는 기존 계산을 유지합니다. 패스는 시트 `트레이닝 패스` A열의 회차별 한섭 날짜(일본 일정 기준)로 오늘 다음 날부터 목표 시작 전날 사이에 시작하는 회차만 세며, 시트 마지막 회차 뒤로는 30일 간격으로 잇습니다. 보상량은 무료 500/티켓 각 2장, 프리미엄 총 1,850/티켓 각 4장/무지개 조각 1개를 시트에서 읽습니다. 기존 유료 구매분 350쥬얼도 유지합니다.
- 시트 갱신: 원본의 `파일 → 다운로드 → Microsoft Excel(.xlsx)` 파일을 준비한 뒤 `python scripts/import-sheet-rewards.py <다운로드한 .xlsx 경로>`를 실행합니다. 외부 수식은 실행하지 않고 파일에 저장된 계산 결과만 읽습니다. 원본 파일의 SHA-256, 시트 이름과 행 번호를 함께 저장합니다. 스토리·레전드의 회차는 원본 표의 순서를 유지합니다.

- 수집 원본: `lib/data/rewards.json`의 1,655개 보상 레코드. 기간 한정 미션·특별 로그인, 스토리 이벤트 포인트·열람·빙고, 신규 캐릭터 스토리 1~4화, 이벤트 한정 교환소·흥행·먼슬리 매치 β와 운영팀 별도 지급을 포함합니다. 상시 월간 교환소, 일반 성장·업적·캐릭터 스토리 5화 이후 보상은 제외합니다. `lib/rewardScope.ts`를 수집·서버 로딩·최종 계산에 공통 적용합니다.
- 별도 보완: 인자연구 총 26회, 기능시험 총 14회, 팀 스카우트 8회, 레이싱 카니발 7회, 마스터즈 챌린지 9회, 쇼타임, 우마 산책, 주년 협동 이벤트(Beyond Memories 등), 기념 한정 교환소. 개최별 수량·출처·수령 조건을 보존합니다.
- 계산 모델은 쥬얼·일반 티켓 외에 무지개/금 해방 결정·결정 조각 및 전용·확정 티켓을 구분합니다. 결정·조각을 쥬얼로 환산하거나 전용 티켓을 일반 픽업 횟수에 합산하지 않습니다. 프리미엄 패스의 무지개 조각도 합산합니다. **기존 화면에는 결정·조각을 별도로 표시하는 UI를 추가하지 않았습니다.**
- 대회: 챔미 일본 2024년 4월 쥬얼 인상과 결승 티켓, LOH 랭크별 쥬얼·티켓·조각을 반영합니다. 미래 개최도 기존 순위 선택을 시트의 최신 PVP 표에 연결합니다. 레전드는 시트에 기재된 개최와 마지막 행 이후의 개최에 회당 500쥬얼·무지개 조각 1개를 합산하며 별도 참가 미션과 중복 계산하지 않습니다. 레전드 참여를 끄면 해당 개최의 주얼과 조각을 함께 제외합니다. 시트 범위보다 앞선 레전드는 기존 상대별 최초 승리 150 + 트로피 최초 획득 100 = 총 250쥬얼·별도 미션 계산을 유지합니다.
- 캐릭터 스토리는 신규 캐릭터 공개 시 1~4화 최초 열람 보상 80쥬얼(20×4)을 캐릭터당 한 번 합산합니다. 의상 변경·복각은 재합산하지 않으며, 5화 이후 보상과 과거 미열람분은 넣지 않습니다.
- 팀·카니발 총보상에 포함된 전용 미션은 중복 합산하지 않습니다. 특별 로그인은 첫날에 전체 기간분을 더하지 않고 일차별로 계산합니다.
- 이벤트는 완주, 교환소는 해당 재화를 가지고 한정 재고를 모두 교환하는 경우의 최대 획득량입니다. 개인별 실제 수령·소비 내역은 연동하지 않습니다. 이미 시작한 보상은 기존 정책대로 제외합니다. 챔미 예선 성적, LOH 상위 순위·추가 점수, 랜덤 드롭은 사용자 조건이 없으므로 확정 지급량에 넣지 않습니다. 미발표 보상과 수량을 확인하지 못한 항목을 임의로 생성하지 않습니다.
- GameTora 미션은 실시간으로 갱신하고, 실패한 자료는 검증된 스냅샷을 사용합니다. 나머지 공개 데이터 스냅샷은 `npm run sync:rewards`로 갱신하며, 수동 보완 자료는 `lib/rewardSupplement.ts`에 있습니다. 신규 공지의 모든 내용을 자동으로 판독하는 구조는 아닙니다.
- 운영팀 지급은 [umapyoi.net 뉴스 API](https://umapyoi.net/docs/news.html)의 공식 공지 보관본 2,728건에서 대조한 112건을 스냅샷으로 보존합니다. 실행 중에는 1시간 캐시로 최신 공지 64건을 재확인하고, 마지막 수집 공지 ID 이후의 신규 공지도 모두 확인합니다. 점검·오류·파카라이브의 명시된 지급 블록에서 주얼·일반/확정 티켓·결정/조각을 읽습니다. 다른 캠페인의 소개나 수량 불명확한 문구는 별도 선물로 만들지 않습니다. 같은 공지의 수정된 금액·날짜·재화는 수동 입력보다 우선하고, 같은 날 같은 금액인 다른 공지는 별도로 유지합니다. 플랫폼 복제 공지와 차액 보전도 중복하지 않습니다. 전체 스냅샷을 갱신하려면 `npm run sync:operator-rewards` 후 `npm run sync:rewards`를 실행합니다. 특정 이용자 대상 보상 조건은 보존하며 실제 계정의 수령 여부는 연동하지 않습니다.
- `lib/data/eventMaster.json`은 공개 일본 마스터 데이터의 이벤트 보상표를 추출한 자료입니다. 원본의 확인 범위는 2025-10-10까지이며 이후 개최분은 GameTora·uma.guide와 출처가 기록된 보완 자료를 병합합니다. 원본 SQLite 파일을 준비하면 `node scripts/extract-event-rewards.mjs <master.mdb 경로>`로 재추출한 뒤 `npm run sync:rewards`를 실행할 수 있습니다.

### 이벤트 일정에 넣는 이벤트

레전드 레이스, 챔피언스 미팅, 리그 오브 히어로즈, 스토리 이벤트, 기능시험, 레이싱 카니발, 팀 스카우트, 주년 기념, G1 기념, 기념 미션. 마스터즈 챌린지는 개최 날짜 자료를 찾지 못해 넣지 않았습니다.

## 규칙

- 모든 데이터는 일본서버 기준입니다.
- 한국서버 예상일 = 일본서버 날짜 + 476일(고정). 화면에는 한국서버 예상일을 메인으로, 일본서버 날짜를 보조로 함께 표시합니다.
- 캐릭터·카드 이름은 한국서버 공식 한글명을 우선하고, 없으면 일본어 원문으로 표시합니다.
- 사료계산기 입력값과 뽑기 기록은 사용하는 브라우저의 `localStorage`에만 저장되며 기기 간 동기화는 없습니다.

## 데이터 출처

외부 API 응답은 Next.js 데이터 캐시에 두며, 보상은 검증된 스냅샷과 출처가 기록된 보완 자료도 함께 사용합니다.

- [umapyoi.net](https://api.umapyoi.net/): 픽업 일정, 일러스트, 생일
- [gametora.com](https://gametora.com/ko/umamusume): 배너·제공 비율, 한국어 이름, 미션·이벤트 보상, 이벤트 일정
- [uma.guide](https://uma.guide/pull-planner/): 일본 게임 데이터의 미션·로그인·스토리 보상 및 이벤트 이력 스냅샷. 글로벌 서버의 정기 수입 설정값은 사용하지 않습니다.
- [결정 조각 배포 이력](https://wikiwiki.jp/vip_umamusu/虹の結晶片（仮), [교환소 재고](https://wikiwiki.jp/vip_umamusu/ショップ): 이벤트 누락과 결정 조각·티켓 교차 확인
- 사이트 아이콘: [Game8의 무지개 편자 이미지](https://game8.jp/umamusume/419913)에서 테두리와 배경을 제거한 투명 PNG (`app/icon.png`, 게임 이미지 저작권: Cygames, Inc.)
- 고정 보상표(로그인 보너스, 팀 경기장, 챔피언스 미팅 등)는 공략 사이트·공식 공지를 근거로 `lib/jewelSources.ts`에 직접 정리

## 기술 스택

- Next.js 15 (App Router), React 19, TypeScript
- 인증·서버 DB 없음
- 배포: Vercel
- 날짜 캐시: Vercel Schedules(`vercel.json`의 `schedules`, Hobby는 최대 15분 늦게 실행)가 한국시간 0시·12시에 `/api/revalidate`를 불러 모든 페이지 캐시를 비운다. Vercel 환경 변수에 `CRON_SECRET`이 있어야 동작한다
